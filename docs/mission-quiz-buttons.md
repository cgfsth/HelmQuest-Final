# Mission quiz button labels

The instructor mission cards used only browser-local quiz assignments to choose Create Quiz or Update Quiz. Existing Firestore quizzes were linked directly through moduleId, and the local cache was not hydrated when instructors opened Mission Management. Consequently, saved quizzes appeared as Create Quiz.

The cards now load the existing GET /api/v1/quizzes response when Mission Management opens, match the mission ID against the saved quiz's moduleId, and refresh when the section reopens. Saved records take precedence over stale browser assignments. Current direct links and legacy array-valued module links use the same matching function; local assignment records remain a fallback while no backend snapshot exists. Loading temporarily disables quiz buttons.

Before opening or creating, the instructor action rechecks the backend list. An existing quiz opens the original document and questions in the existing editor. Only a successful response without a matching quiz proceeds through the existing creation flow. A lookup error does not create a quiz. The snapshot updates immediately after creation or saving. Quiz questions, grading, scores, student submission flow, and backend write routes retain their existing behavior.

Files: src/App.vue and tests/mission-quiz-button.test.mjs. Eight focused regression tests cover backend-driven labels without local assignments, section reopening, existing editor selection without creation, creation after confirmed absence, failed lookups, local schema compatibility, array links, and stale account responses. The live browser check in scripts/verify-live-instructor-overview.mjs also verifies mission labels and opening a saved quiz without creating or saving records.

Verified against the running app: all three current missions displayed Update Quiz, a mission ID without a saved quiz returned Create Quiz, and clicking Update Quiz opened an existing document with its saved questions. The database still contained three quizzes. All 49 frontend tests and the production build passed (the existing bundle-size warning remains). Actual live quiz creation/saving was not exercised; the absent-quiz creation path was checked with the real frontend handler and a mocked API. The stopped frontend dev server was restarted at http://localhost:5174; the existing backend continues at http://localhost:3001.
